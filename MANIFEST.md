## 🚀 Quick Start

### Option 1: One-Command Setup (Recommended)

```bash
cd openshell-claude-code-config
bash scripts/setup.sh
# Then follow the prompts
```

### Option 2: Manual Setup

```bash
cd openshell-claude-code-config

# 1. Build image
podman build -f docker/Dockerfile -t openshell-claude-code:latest .

# 2. Start gateway
cd docker
podman compose up -d
cd ..

# 3. Register gateway
openshell gateway add http://localhost:8080 --name openshell-local

# 4. Create sandbox
openshell sandbox create --name demo \
  --image openshell-claude-code:latest \
  --policy policy/base-policy.yaml

# 5. Run Claude Code
openshell sandbox run demo -- claude --help
```

## 🔐 Authentication (NEW!)

### Development Mode (Insecure - Local Only)

```toml
# docker/gateway.toml
[openshell.gateway.auth]
allow_unauthenticated_users = true
```

✅ Good for: Learning, testing, local development  
❌ Bad for: Production, shared systems

### Production Mode (Secure)

**Option 1: OIDC with Keycloak (Recommended)**

```bash
bash scripts/setup.sh --with-keycloak
```

Then configure in `docker/gateway.toml`:
```toml
[openshell.gateway.oidc]
issuer_url = "http://keycloak:8080/realms/openshell"
client_id = "openshell-gateway"
client_secret = "your-secret"
redirect_uri = "http://localhost:8080/oauth2/callback"
```

**Option 2: OAuth2 with GitHub**

```toml
[openshell.gateway.oauth2]
provider = "github"
client_id = "your-client-id"
client_secret = "your-client-secret"
redirect_uri = "http://localhost:8080/oauth2/callback"
```

See **[auth/AUTHENTICATION.md](openshell-claude-code-config/auth/AUTHENTICATION.md)** for complete guides.

## 🎯 What Each File Does

### Gateway Configuration (`docker/gateway.toml`)

**Controls:** How sandboxes are created, what authentication is used

```toml
[openshell.gateway]
compute_driver = "podman"           # Use Podman (not Docker)
disable_tls = true                  # Dev mode (disable for prod)

[openshell.gateway.auth]
allow_unauthenticated_users = true  # Dev mode

# PRODUCTION: Use OIDC
# [openshell.gateway.oidc]
# issuer_url = "..."
# client_id = "..."
# client_secret = "..."
```

### Container image recipe (`docker/Dockerfile`)

**Controls:** What tools are available in the sandbox

```dockerfile
FROM ubuntu:24.04
RUN apt-get install ... nodejs python3 ...
RUN npm install -g @anthropic-ai/claude-cli
RUN useradd -r claude  # Non-root user (security!)
```

### Security Policy (`policy/base-policy.yaml`)

**Controls:** What Claude Code is allowed to do

```yaml
filesystem_policy:
  read_only: [/bin, /usr, /lib]      # System: read-only
  read_write: [/sandbox, /tmp]       # Workspace: writable

network_policies:
  anthropic:
    endpoints:
      - host: api.anthropic.com
        port: 443
        enforcement: enforce          # Hard deny if not matched
```

## 🔒 Security Layers

```
Layer 1: Gateway Config
└─ Specifies image, authentication, JWT keys

Layer 2: Container Image
└─ Non-root user, available tools, working directory

Layer 3: Kernel Policy
└─ Landlock (filesystem), seccomp (syscalls), network proxy
   ↓
SECURE SANDBOX ✓
```

**Why three layers?** If one is compromised, others still protect.
